# 첫 완성 목표: 텐서 프로그램으로 리눅스 사용

사용자 목표는 프로그래밍 언어로 작성할 수 있는 동작을 학습 가능한 벡터 프로그램으로
표현하는 것이다. 첫 완성 목표는 리눅스에서 파일·디렉터리·프로세스·표준 입출력·
네트워크를 사용하고, 이 기능들을 조건과 반복으로 조합하는 텐서 프로그램이다.
OS 실행 의미는 호스트 계층이 제공하고, 작업 절차와 호출·제어는 텐서 파일에 둔다.
아는 기능은 계약 ID로 바로 호출하며, 모르는 기능은 근거를 받아 제한된 학습을 진행한다.

## 완성 판단 기준

다음 항목을 같은 프로그램 파일의 저장·재로드와 학습하지 않은 입력에서 검증한다.

1. 파일 읽기/쓰기/이동/삭제, 디렉터리 생성/조회/삭제와 상태 확인.
2. 목록·문자열·구조화된 결과를 처리하고 여러 파일을 조건에 따라 순회해 변환·집계.
3. 프로세스를 인자·실행 디렉터리·환경과 함께 시작하고 표준 입출력, 종료 코드,
   시간 제한과 실패를 처리. 파이프와 다른 프로그램의 결과를 작업에 연결.
4. 네트워크 입출력과 시스템 메타데이터를 사용하고, 실패/자원 해제를 포함해 조합.
5. 사람의 요청에서 학습 목표를 준비하고 독립된 근거로 검증. 배운 기능의 실행은
   LLM 없이 수행하며, 실패한 후보는 등록하지 않고 기존 기능을 보존.

각 범위의 미사용 검증 사례와 실패 사례가 통과해야 한다. 일부 사례의 성공만으로
리눅스 전체를 사용할 수 있다거나 모든 프로그램을 대체한다고 판정하지 않는다.
범용 계산·자료구조·동시성·외부 라이브러리로의 확장은 장기 목표로 유지한다.

## 이번 구현: 파일시스템 기반

기존 버퍼와 파일 읽기/쓰기에 다음 실행 의미를 추가했다. 제공 기능 자체는 학습된
작업이 아니다. 기존 프로그램은 기본 6개 기능을 유지하며 새 기능을 명시적으로 설치한다.
`runtime.provide_host_operations(operations)` 또는 초안의 `allowed_operations`를 사용한다.

| 호스트 기능 | 입력 | 출력 / 의미 |
|---|---|---|
| `path.exists` | 경로 | 존재하면 1, 없으면 0 |
| `file.move` | 원본, 목적 경로 | 파일 이동, 기존 목적 파일 대체, 성공 1 |
| `file.remove` | 경로 | 파일 하나 삭제, 성공 1 |
| `directory.create` | 경로 | 부모가 존재할 때 디렉터리 하나 생성, 성공 1 |
| `directory.remove` | 경로 | 빈 디렉터리 삭제, 성공 1 |
| `directory.list` | 경로 | 직계 항목 이름을 정렬한 UTF-8/NUL 구분 버퍼 |

목록은 파일과 디렉터리 이름을 포함하며 하위 내용을 재귀로 펼치지 않는다.
줄바꿈이 들어간 파일명도 NUL 구분으로 보존한다. 시스템 명령 `ls`를 실행하지 않는다.
학습한 `save_listing`은 조회 후 저장하는 두 호출을 텐서 절차로 발견한다.
학습한 `make_copy`는 디렉터리 생성·파일 읽기·쓰기의 세 호출과 인자 경로를 발견한다.
커널에 이 작업 이름별 분기를 추가하지 않았다.

### 디렉터리 상태 학습과 검증

상태 예제에 `before_directories`와 `after_directories`를 추가했다. 각각 정규화된
상대 경로 목록이며 비어 있는 폴더를 표현한다. 파일/폴더 경로에서 부모 디렉터리는
추론한다. 파일과 디렉터리가 같은 경로를 차지하는 상태는 거절한다.

학습과 카탈로그 검증 모두 전체 파일 내용 및 디렉터리 집합을 정확히 비교한다.
새로 생긴 불필요한 폴더도 실패다. 기존 예제는 목록을 생략할 수 있으며, 파일 경로의
부모를 사용한다. 메모리 호스트의 파일 쓰기도 부모가 없으면 실제 OS처럼 실패한다.
파일을 삭제해도 부모 디렉터리는 남으므로 목표에 빈 부모 상태를 명시해야 한다.
학습은 메모리 호스트에서만 진행하며 실제 파일 변경은 등록된 기능 실행 때 수행한다.

### 재현과 측정

```powershell
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m pytest -q tests/test_linux_filesystem.py
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python experiments/linux_filesystem.py
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m pytest -q
```

실험은 이미 존재하는 결과 디렉터리를 덮어쓰지 않는다. 반복은 `--output`에 새 경로를
준다. `results/linux_filesystem/curriculum.json`은 학습 전에 고정한 예제이고,
`program.pt`는 학습 기능과 계약이 축적된 하나의 텐서 파일이다.
`verification.json`에 학습 기록, 호출 결과와 전체 최종 스냅샷을 보존한다.

7개 기능을 한 파일에 학습해 저장한 뒤 리눅스의 새 루트 4개에서 재학습 없이 실행했다.
미사용 데이터는 빈 파일, 바이너리를 포함한 새 문자열, 모든 바이트 값, 4096바이트다.
각 루트에서 생성·복사·조회 결과 저장·이동·존재 확인·파일 삭제·빈 폴더 생성/삭제를
수행했고 전체 최종 상태가 기대와 일치했다. 4/4 통과, 총 36개 계약 호출이다.
프로그램 SHA-256: `9963ccb7b0a4404b12dc7d8e0594aa713f114ae34db762664208a57df79d2b53`.
LLM 및 검색 인코더를 import하지 않았다. 테스트는 같은 `vectorpro-test` 하나만 사용했다.

전용 테스트는 실제/가상 호스트의 정상·오류 상태 일치, 저장 호환, 경로 이탈 거절,
버퍼 한도, 전체 디렉터리 상태 비교 및 메모리 학습을 검증한다.
전용 테스트 **15 passed, 2.72초**, 최종 전체 회귀 **238 passed, 195.02초**.
실험의 호출 순서는 평가용 시나리오다. 36개 호출 전체가 하나의 학습 절차라는 뜻은
아니며 각 등록된 기능의 내부 절차를 학습한 것이다.

### 아직 남은 범위

목록/UTF-8/JSON 바이트 연산, 제한된 역순 목록 본문 탐색을 추가했다.
직계 파일의 일괄 복사와 JSON 문자열 필드 저장을 학습해 미사용 루트에서 검증했다.
파일명 접미사에 따른 조건부 복사와 학습 산술을 이용한 파일 크기 합산도 검증했다.
완료 범위와 제한은 [STRUCTURED_DATA.md](STRUCTURED_DATA.md)를 참고한다.

현재 단계는 첫 완성 목표의 파일시스템 기반이다. 프로세스/파이프/환경/권한/시스템
정보/네트워크와 임의의 중첩 조건·문자열 처리·자료구조는 아직 구현하지 않았다.
다음 단계는 구조화된 값과 여러 결과의 전달·학습 기반을 만든 뒤 프로세스의
표준 입출력 및 종료 결과를 연결하는 것이다.

현재 경로는 호스트 루트 안의 이식 가능한 UTF-8 상대 경로이며 `.`·절대 경로,
`..`·역슬래시·콜론·NUL을 거절한다. 리눅스의 모든 파일명/권한/심볼릭 링크 의미를
구현하지 않았다. 링크는 기존 호스트의 resolve 규칙을 따른다. 파일 이동은 같은
파일시스템 내 이동이며 디렉터리 이동·재귀 삭제는 제공하지 않는다.
native 실행 중 뒤쪽 호출이 실패했을 때 앞선 변경을 되돌리는 트랜잭션은 없다.
시간·용량 한도와 검증 성공은 범용 정확성이나 사용자의 의도에 대한 증명이 아니다.
macOS 검증은 사용자의 요청에 따라 뒤로 남긴다.
