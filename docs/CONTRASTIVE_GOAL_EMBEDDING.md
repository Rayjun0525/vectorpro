# 의미 대비 학습 실험

2026-10-05. ‘같은 동작의 표현은 가깝게, 보존/삭제와 이동 방향이 다른 표현은
멀게’ 학습하는 경로를 구현·시험했다. 목표 선택 앞단의 실험이며 리눅스 작업
절차 학습이나 실행 커널 변경은 아니다. 두 방법 모두 자동 실행에 채택하지 않았다.

## 데이터와 경계

기존 프로그램의 호출자 형식 교사 예제43개와 목표 규칙을 그대로 사용했다.
이 라벨은 실험 작성자가 제공한 것이며 실제 사용자 확인 이력이나 자율적으로
발견한 정답은 아니다. 같은 목표끼리 양성 쌍, 다른 목표끼리 음성 쌍을 만든다.
미지원/모호한 예제는 기존처럼 하나의 None 그룹이며 그 그룹이 모든 미지원
요청을 대표한다고 보장하지 않는다.

평가에서는 새 문장을 추론/학습 전에 파일로 고정하고 교사 예제와 중복을 검사했다.
조건부/변환/모순/미지원 요청의 거절과 지원 요청의 정확한 목표 선택을 따로 센다.
지원 요청의 보류는 실패다. 목표 규칙/허용 변경 목록의 순서를 정규화해 비교하며
모든 논리적 동등성을 판정하는 평가는 아니다. 기대 목표는 채점에만 사용한다.
생성형 LLM 호출/모의 호출자 추가 답변은0회다. 설치된 MiniLM 문장 인코더는 사용한다.

## 방법1: 학습한 벡터 거리

experiments/contrastive_goal_embedding.py는 기존384차원 임베딩에 적용하는
384×384 변환 W를 학습한다. z=normalize(xWᵀ), 같은 목표 쌍의 코사인은1,
다른 목표 쌍은0으로 유도한다. 양성/음성 평균 손실을 따로 내어 균형을 잡는다.
정규화0.001, Adam 학습률0.01, 전체 배치400회는 실행 전에 고정했다.
기본 MiniLM의 가중치는 이 실험에서 변경하지 않는다.

예제43개에 대한 손실은0.45918→0.000020으로 줄었다. 학습 시간은1.61초다.
이 감소는 교사 데이터를 잘 맞춘다는 뜻이지 새 요청을 정확히 이해한다는 증거는 아니다.
프로젝터를 저장·복원하고 변환된 예제 벡터로 기존 GoalMemory 최근접 검색을 사용했다.
최소유사도0.55/다른 목표와 차이0.03은 기존 최근접과 같은 값이며 확률이 아니다.

기존16건은 진단 재시험이고, 새24건(지원16/미지원8)은 독립 검사로 구분했다.
새 파일명 alpha.dat/omega.dat, 영어/한국어 보존/삭제/역방향과 미지원 효과를 포함한다.

| 새24건 | 전체 맞음 | 지원 목표 맞음 | 오답 초안 |
|---|---:|---:|---:|
| 기존 최근접43 | 15/24 | 10/16 | 6 |
| 기존 합의43 | 10/24 | 2/16 | 0 |
| 학습한 벡터 거리43 | 11/24 | 6/16 | 6 |

학습한 벡터 거리는 기존 최근접보다 개선되지 않았다. 작은 교사 집합에 거의
완벽히 맞는 변환도 새 문장에서 의미 정확도가 낮을 수 있음을 확인했다.
결과: results/contrastive_goal_embedding의 protocol/heldout/summary.json,
projection.pt, program.pt. 구형 기본 프로그램과 설치 모델 파일은 변경하지 않았다.

## 방법2: 문장 인코더 마지막 층 직접 학습

첫 방법의 실패를 보고 experiments/contrastive_encoder_benchmark.py에서 실제
MiniLM 마지막 Transformer 블록을 학습했다. 나머지 층·토크나이저는 고정하고
dropout을 비활성화했다. 고정된 앞부분의 교사 토큰 상태를 캐시해 같은 모델의
마지막 블록만 반복 계산한다. 작업 전용 문자열 파서나 Python 작업 절차는 없다.

양성/음성 코사인 손실에 기존 임베딩과의 차이 벌점0.05를 더했다. Adam 학습률
0.0001,100회는 실행 전에 고정했고 검증 점수로 조기 종료/임계값을 선택하지 않았다.
훈련 손실0.45918→0.01620, 학습11.81초. 모델 로딩/평가 시간은 이 시간에 포함하지 않는다.
마지막 블록만 약7.1MB 체크포인트로 보관하고 설치된 전체 모델은 덮어쓰지 않았다.

첫 새24건은 이 방법에서는 진단 재시험이다. 별도의 새16건(지원12/미지원4)을
학습 전에 고정하고 기존 최근접/합의/프로젝터/마지막 블록을 같은 요청으로 비교했다.
새 파일명 input-x.bin/archive-y.bin과 부정/방향/미지원 표현을 포함한다.

| 새16건 | 전체 맞음 | 지원 목표 맞음 | 오답 초안 |
|---|---:|---:|---:|
| 기존 최근접43 | 5/16 | 3/12 | 7 |
| 기존 합의43 | 5/16 | 2/12 | 1 |
| 학습한 벡터 거리43 | 8/16 | 6/12 | 6 |
| 마지막 블록 학습43 | 8/16 | 6/12 | 6 |

지원 요청의 처리 수는 늘었으나 오답도 늘어 안전한 개선으로 채택하지 않았다.
마지막 층 학습이 프로젝터보다 나은 결과도 이 검사에서는 없었다. 기존 합의도
새16건에 오답1건을 내므로 과거 소표본의 오답0을 범용 보장으로 해석하지 않는다.
첫24건의 진단에서 마지막 블록은 지원10/16이나 미지원 오류를 포함해 오답11건이었다.
단순히 처리 수만 보고 좋은 모델이라고 결론내리면 안 된다.

원시 결과: results/contrastive_encoder의 protocol/validation/summary.json,
last_block.pt, program.pt. 각 프로그램에는 해당 인코더 신원과 재계산된 예제 벡터를
기존 형식으로 저장했다. 실험용 프로젝터/마지막 블록 체크포인트는 별도 연구
아티팩트이며 한 프로그램 파일만으로 새 인코더까지 배포하는 기능은 아직 구현하지 않았다.
기본 CLI에 이 파일을 연결하거나 학습 결과를 자동 승인하지 않는다.

## 검증과 재현

양성/음성 쌍이 없는 학습 거부, 원본 벡터 보존, 투영 체크포인트 복원, 손상된
가중치 거부를 검사했다. 작은 실제 Bert 모델로 마지막 블록만 바뀌고 앞부분은
바이트 단위로 동일하며, 원본+체크포인트로 만든 새 모델 출력이 같음을 검증했다.
학습 후 파라미터의 gradient를 비활성화하는 경계도 확인했다. 관련40 passed (7.15초).
전체 회귀 **398 passed (282.65초)**. 의미 평가의 오답은 회귀 테스트 통과와 별도로
위 표에 기록했으며, 회귀 통과를 자연어 정확도 보장으로 표현하지 않는다.

```powershell
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m experiments.contrastive_goal_benchmark --output results/contrastive_goal_embedding_recheck
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m experiments.contrastive_encoder_benchmark --output results/contrastive_encoder_recheck
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m pytest -q tests/test_contrastive_encoder.py tests/test_contrastive_goal_embedding.py tests/test_goal_memory.py tests/test_goal_condition_search.py tests/test_goal_questions.py tests/test_goal_evidence.py
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m pytest -q
```

두 번째 실험은 최초 results/contrastive_goal_embedding/projection.pt와 heldout.json을
읽어 같은 첫 모델/사례와 비교한다. 재시험 결과를 독립 표본에 합산하지 않는다.
기존 vectorpro-test 하나/기존 python:3.12-slim/설치된 모델을 재사용했다.
이미지 빌드·컨테이너 생성·모델 다운로드는 없다.

## 현재 위치와 남은 것

대비 학습을 실제로 구현하고 저장·복원·새 요청 평가까지 완료했다. 그러나 현재
교사43개/제한된 목표로는 정확하고 넓은 자율 실행을 달성하지 못했다. 개선 후보는
방향·부정·경로 역할·미지원 효과의 더 다양한 검증된 대비 데이터, 독립된 보정
집합에서 처리율과 오답률을 함께 확인하는 것, 의미가 확정된 계약 입력과 연결하는
것이다. 더 큰 모델이면 해결된다거나 학습을 반복하면 저절로 정확해진다는 결론은
이 실험으로 내릴 수 없다. 리눅스 실행 기능의 범위 확장과 의미 정확성은 별도 과제다.
