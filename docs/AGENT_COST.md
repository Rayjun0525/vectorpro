# 에이전트 반복 실행 비용 측정

2026-10-04, 기존 `vectorpro-test`에서 로컬 Gemma 3 1B Instruct Q8_0을 실제 실행했다.
작업은 새 폴더 생성 → 원본 파일 읽기 → 목적 파일 쓰기다. 빈 파일부터 4096바이트까지
6개 입력을 먼저 고정했다. 검증용 정답 파일 내용을 모델에 제공하지 않았으며 요청과
도구 설명만 제공했다. JSON schema 제약은 모델이 도구와 값을 선택하는 범위를 정한다.

## 결과

| 방식 | 성공 | LLM 호출 합계 | 입력+출력 토큰 합계 | 작업 시간 중앙값 |
|---|---:|---:|---:|---:|
| LLM이 기초 도구를 순서대로 선택 | 1/6 | 24 | 12,106 | 16.169초 |
| LLM이 학습된 텐서 기능 하나 호출 | 0/6 | 6 | 1,695 | 7.755초 |
| LLM이 Python 함수 하나 호출 | 0/6 | 6 | 1,695 | 6.477초 |
| 구조화 인자로 텐서 직접 호출 | 120/120 | 0 | 0 | 82.54ms |
| 구조화 인자로 Python 직접 호출 | 120/120 | 0 | 0 | 12.53ms |

직접 호출은 같은 6개 사례를 각 20회 반복한 것이다. 120개의 독립적인 새 작업이 아니다.
LLM 각 방식은 6회 평가했다. 표의 토큰/호출은 각 방식의 전체 합계이며 시간은
실패를 포함한 한 작업 시도의 중앙값이다. 성공률이 다른 경로를 성공당 비용이 같다고
비교하면 안 된다. 여러 호출을 묶으면 호출 수와 토큰은 줄었지만 이번 작은 모델은
정확한 결과를 만들지 못했으므로 생산성 개선을 입증한 결과가 아니다.

### 결론

계약 ID와 정확한 구조화 인자를 프로그램이 제공하면 실행 단계의 LLM 사용은 0으로
줄어든다. 실제 반복 실행도 모두 성공했다. 다만 이 경로는 자연어 해석을 생략한다.
LLM이 매번 계약 인자를 준비하는 현재 형태는 신뢰하기 어렵다. 결합 도구의 목적 경로를
`job-N/result.bin` 대신 `result.bin`으로 넘겼고, 기초 도구 경로는 폴더/파일/버퍼를
혼동했다. 텐서 실행기가 틀린 요청 값을 원래 의도에 맞게 고쳐주는 구조는 아니다.

같은 작업의 Python 직접 함수가 텐서보다 약 6.59배 빠르다. LLM 생략의 이점은
재사용 가능한 스크립트에도 존재한다. 텐서의 고유 장점은 절차를 예제에서 획득하고
검증·축적하는 방식이며, 이번 측정은 실행 속도 자체의 우위를 보여주지 않았다.

## 방법과 범위

- 같은 모델을 한 번 로딩하고 한 토큰으로 워밍업했다. 모델 로딩 1.063초,
  워밍업 1.316초는 반복 시간에서 제외해 별도 기록했다.
- 텐서 절차는 새로운 런타임에서 상태 예제로 학습했다. 학습 0.272초, 저장 0.036초,
  파일 재로드 0.015초다. 예제 작성·정답 생성 비용은 포함하지 않았다.
- 직접 호출은 런타임을 유지하며 매번 새 호스트 핸들을 사용했다. 파일 준비와
  사후 검증은 시간에서 제외했고, 계약 검증과 실제 읽기/쓰기는 포함했다.
- Python 함수는 비교용으로 사람이 작성한 세 단계 함수다. 학습된 프로그램이라고
  부르지 않는다. LLM 결합 도구는 Python/텐서에 동일한 schema와 요청을 사용했다.
- LLM 경로 순서는 사전 고정 난수로 섞고, 직접 Python/텐서 순서는 번갈아 실행했다.
  모델의 프롬프트 캐시가 반복 요청을 돕는 효과를 완전히 제거하지 않았다.
- 정상 `make_copy` 또는 `write_file` 실행 후 멈추고, 전체 파일·디렉터리 상태로
  성공을 독립 판정한다. 도구 오류는 최대 6회 호출까지 재시도한다.
- `/workspace` 프로젝트 마운트에서 실행해 해당 파일시스템 지연을 포함한다.
  컨텍스트 8192, llama.cpp CPU 스레드 4, temperature 0, seed 0이다.
- API 요금·전력·메모리 비용은 측정하지 않았다. 토큰 수는 LLM 사용량의 지표이며
  실제 청구액이 아니다. 다른 모델·장비·에이전트·작업으로 일반화하지 않는다.

## 원시 자료와 재현

`results/agent_cost_final`에 사전 protocol, 직접 호출 240개 기록, 실제 LLM 36개
호출의 원문·usage, 전체 최종 상태, summary, environment와 학습된 `program.pt`를
보존했다. 모델 SHA는 `b205840c5dcef55078e37d344677869a714ffd42a4ae448c48dcfb52e4bb10d5`다.
결과의 native 작업 파일은 재생성 가능한 시험 자료라 Git에서 제외한다.

```powershell
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python experiments/agent_cost.py --output results/agent_cost_replay --repeats 20
```

이미 존재하는 결과는 덮어쓰지 않는다. 최초 예비 실행은 성공하지 못한 상태에서도
측정기가 계속 호출을 요구해 비용을 부풀렸으므로 중단하고 `results/agent_cost`에
제외 사유와 원문을 남겼다. 최종 실행은 중단 규칙만 수정했고 모델·요청·도구·정답은
튜닝하지 않았다. 어댑터/학습기/실행 커널을 변경하지 않았다.

현재 리눅스 파일시스템 단계에서 호출 비용을 측정했다. 다음 비용 최적화 과제는
계약 인자의 경로·버퍼 역할을 정확하게 전달하고, 검증된 구조화 호출을 재사용하는
것이다. 목록·구조화 결과, 프로세스·파이프·네트워크 구현 과제도 그대로 남아 있다.
