# LLM 없는 유사 요청 검색과 조건 구별 검증

2026-10-05. 텐서 파일의 요청 임베딩으로 유사 기능을 찾고 보존/삭제/방향도
구별할 수 있는지 검증했다. 기존 컨테이너 vectorpro-test와 설치된 MiniLM만
사용했다. 생성형 LLM 호출과 모의 호출자 답변은 모두0회다. 문장 인코더는 사용한다.

## 실험 방법

기존 프로그램 results/goal_router_execution_replay/program.pt 안의 예제43개,
목표 규칙, 저장 벡터와 인코더 신원을 읽었다. 별도 기능 메타파일 없이 기존
정보에서 후보를 얻는다. 원본 프로그램과 기본 실행 경로는 변경하지 않았다.

experiments/goal_condition_search.py는 각 목표를 인자별 최종 상태와 허용 변경
목록으로 분해한다. 같은 고정 문장 벡터에서 조건별 ridge 분류기를 학습한다.
정규화0.05, 최소점수0.6, 차순위 차이0.2는 실행 전에 고정했고 새 결과를 보고
바꾸지 않았다. 각 조건이 충분히 구별되고 전부 만족하는 기존 목표가 하나인
경우에만 needs_goal_review를 반환한다. 미지원·경합·조건 불일치는 보류한다.
점수는 확률이 아니며 같은 인코더의 조건 판단들은 독립된 의미 증거가 아니다.

이 분류기의 가중치는 실험 시작 때 기존 저장 벡터에서 유도하고 메모리에서만
사용한다. 실험용 파생 가중치를 새 프로그램 저장 형식에 추가하지 않았다.
학습한 실행 절차가 아니라 자연어 목표를 선택하는 앞단의 비교 실험이다.

새 문장16개를 추론 전에 cases.json에 고정했다. 영어/한국어의 정방향/역방향,
보존/삭제 최소 차이 쌍과 전체 보존/대상 삭제, 모순/변환/암호화/모호한 요청을
포함한다. 기대 조건은 채점에만 쓰고 인코더·분류기·검색에 넣지 않는다.
지원12개, 미지원·모순·모호4개다. 후보 검색/판단은 실제 문자열만 입력받는다.

## 결과

| 방식 | 전체 맞음 | 지원 목표 맞음 | 잘못된 초안 |
|---|---:|---:|---:|
| 기존 ridge_consensus | 7/16 | 3/12 | 0 |
| 조건별 벡터 분류 | 5/16 | 1/12 | 1 |
| 기존 방식과 조건별 방식의 추가 합의 | 5/16 | 1/12 | 0 |

조건별 분해는 개선되지 않았다. 잘못된 제안은 ‘source를 destination으로 전달하고
source 삭제’에 destination을 source로 옮기는 역방향 목표를 골랐다. 세 조건 모두
점수 약0.70/차이 약0.52로 높았다. 문장 벡터에 같은 방향 혼동이 있으면 조건을
여러 개로 분류해도 함께 틀릴 수 있다. 기본 검색/실행 경로에 채택하지 않았다.
이번 결과로 임계값/교사 예제를 조정하거나 같은 문장을 새 독립 평가로 재사용하지 않았다.

검색과 최종 선택을 구분하기 위해 같은16개 문장의 후보 순위도 따로 진단했다.
미지원 그룹을 제외한 여섯 양성 목표에서 **정답 후보의 검색 순위**는 다음과 같다.

| 후보 수 | 지원12개 중 정답 포함 |
|---|---:|
| 1개 | 4/12 |
| 2개 | 7/12 |
| 3개 | 10/12 |
| 6개 | 12/12 |

상위3개의10/12는 검색 가능성을 보여주지만, 최종 선택 정확도나 지원 여부 판단이
아니다. 6개는 정의된 모든 목표를 나열하므로12/12가 당연하며 검색 개선 성과로
취급하지 않는다. 여러 인터페이스/새 기능까지 검색할 수 있다는 증거도 아니다.
벡터 검색으로 후보를 찾는 방향은 가능하지만, 실행 결과가 달라지는 조건까지
현재 인코더로 정확히 구별하는 문제는 해결하지 못했다.

## 텐서 실행으로 확인한 것

조건별 방식이 제안한 두 목표에 대해 기존 저장 복사/이동 계약의 정·역방향
입력 연결을 실행했다. 모든 후보는 매번 새 MemoryHostContext에서 세 가지
바이트 입력을 받으며 전체 파일/빈 디렉터리 상태를 목표 검사기로 확인한다.
native 요청 파일에 접근하지 않으며 후보 탐색·실행 중 새 기능 학습도 없다.

정확한 역방향 이동 제안과 잘못된 역방향 이동 제안 모두, 제안된 목표에는 맞는
저장 텐서 경로가 있었다. 이것이 핵심 반례다. **텐서가 선택된 목표를 정확히
실행한다는 사실만으로 그 목표가 원래 자연어 요청과 같다는 것을 증명할 수 없다.**
검증 결과의 matching_tensor_routes는 제안 목표에 대한 일치이며 독립적인
사용자 의도 인증이 아니다. 역할/실제 파일명 연결도 고정된 시험 입력이므로
자연어의 임의 경로를 자동 추출한 결과라고 하지 않는다.

기록: results/goal_condition_search/cases.json, summary.json,
results/goal_condition_recall.json. 원본 프로그램 파일 바이트가 그대로인지도 검사했다.

## 재현과 현재 위치

```powershell
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m experiments.goal_condition_benchmark --output results/goal_condition_search_recheck
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m experiments.goal_condition_report
nerdctl exec -e OMP_NUM_THREADS=1 -e MKL_NUM_THREADS=1 vectorpro-test python -m pytest -q tests/test_goal_condition_search.py tests/test_goal_memory.py tests/test_goal_questions.py tests/test_goal_evidence.py
```

집계 스크립트는 최초 실험 경로를 읽는다. 기존 결과를 덮어쓰지 않는다.
관련 **35 passed (4.52초)**. 새 조건 조회가 저장 예제를 바꾸지 않으며 LLM/호스트
실행 없이 리뷰 초안만 반환하고, 경합/미지원 입력을 보류하는 경계도 검사했다.
학습기·커널·프로그램 저장 형식은 변경하지 않아 전체 회귀는 직전392 passed
(261.70초) 기록을 유지한다. 이번 변경은 실험/시험/문서만이며 새 전체 실행 횟수로
표현하지 않는다.

현재 위치는 ‘LLM 없이 후보 검색 가능, 자율적인 의미 확정은 미해결’이다.
다음 과제는 방향/부정을 구별하는 표현·대비 학습 데이터 개선을 별도 검증하거나,
명확한 구조화 입력/확인된 계약 연결을 사용해 의미 추측을 줄이는 것, 역할/경로
확정과 프로세스/네트워크 목표로 평가 범위를 넓히는 것이다. 모델 크기만의 문제나
이 시스템 전체가 불가능하다는 결론은 이 소표본으로 내리지 않는다.
